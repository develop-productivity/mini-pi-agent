# 做成 monorepo

2026-10-24 · 用户拍板做 monorepo，AI 起草方案 · 已执行

相关决定：[做成 npm workspaces monorepo](../decisions/2026-10-24-monorepo.md)。参考 pi 的分层（ai / agent / coding-agent）。

## 要解决什么

原来是单包：`src/{core,providers,tools}`。要让三层架构在目录上分开，层之间只能通过包的公开入口互相引用；同时有自己的 AGENTS.md、CLAUDE.md，以后功能开分支、走 PR，由 CI 检查。

## 方案

| 方案 | 做法 | 取舍 |
|---|---|---|
| A. npm workspaces，包直接导出 TS 源码（选这个） | 根 `package.json` 写 `workspaces: ["packages/*"]`；每个包的 `exports` 指向 `./src/index.ts` | 不需要构建，`tsx` 直接跑；已经在用 npm |
| B. 每个包编译到 `dist/` | 每个包有 build | 多一层构建，没有发 npm 包的需求 |
| C. pnpm / turborepo | 换包管理器或加任务编排 | 三个包用不上 |

```text
packages/
├── ai/            @mini-pi/ai      原 src/providers/
├── agent/         @mini-pi/agent   原 src/core/ + src/tools/
└── coding-agent/  （待建）          宿主、sandbox、session、hooks、plugins
demo/              单文件 demo，不依赖任何包
scripts/smoke.ts   冒烟测试
```

- 依赖只能往下：`coding-agent → agent → ai`。
- 这次只建 `ai`、`agent`；`coding-agent` 等写 CLI 宿主时再建。指向不存在文件的 `cli`、`tui` 脚本先删掉。
- `tools/registry.ts` 整个文件先放进 `agent`，只搬家、只改 import 路径；写 sandbox 时再把内置工具挪到 `coding-agent`。
- CI：`npm ci` → `npm run smoke` → `npm run typecheck`。typecheck 有 wip 错误，先 `continue-on-error`，最小循环跑通后去掉。
- 本次改动走分支 `chore/monorepo`，提 PR 合入。

## 风险

- 只是文件搬家，`git mv` 保留历史；在分支上做，PR 不合就等于没发生，合了也能 `git revert`。

## 怎么验证

1. typecheck 错误搬家前后相同（13 个，内容一致）。
2. `npm install` 后 `node_modules/@mini-pi/*` 是指向 `packages/*` 的软链接。
3. `npm run smoke` 通过：两个包按包名导入，mock 要工具 → 执行 → 喂回结果 → 结束。
4. `npm run demo:mock` 照常能跑。
5. PR 上 CI 跑出结果。

## 自审结论

没有和已有决定冲突，可回滚，有可检查的验证步骤，照此执行。改了目录结构和 CI，触发代码审查，见 [reviews/2026-10-24-monorepo.md](../reviews/2026-10-24-monorepo.md)。
